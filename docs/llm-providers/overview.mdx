---
title: "Provider Connections"
description: "Provider-native adapters, model discovery, and automatic routing"
---

Open `/connect` in the TUI. Only providers with an installed `ProviderAdapter` v2 and a complete field schema appear as connectable.

Built-in adapters cover OpenAI, Anthropic, Google Gemini, OpenRouter, TokenRouter, Groq, Mistral, DeepSeek, Together AI, Fireworks AI, Ollama, and Custom OpenAI-compatible endpoints. Cloud, OAuth, deployment-based, or other providers require an adapter plugin that implements their native authentication and discovery lifecycle.

Connections and models have separate lifecycles:

1. `/connect` creates or rotates a credential-bearing connection.
2. `/models` discovers and enables models for that connection.
3. `/router` selects among enabled models per task; there is no global model selection.

Base URL is shown only by Custom OpenAI-compatible or adapters that explicitly declare an advanced override. Models.dev contributes metadata, while a signed Strix policy registry contributes pentest quality tiers. Remote registries are data only and never install executable provider code.

Environment credentials are detectable connection hints. They do not override saved TUI choices.
