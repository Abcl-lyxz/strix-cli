## Setup

```bash
git clone https://github.com/usestrix/strix
cd strix
make dev-install
```

Run the application from source with `uv run strix`. Configure test providers inside `/connect`; do not add local keys to the repository or process arguments.

## Validation

```bash
make format
make check-all
```

Formatting is intentionally separate. `make check-all` is non-mutating and runs Python lint/format-check, mypy, Bandit, pytest, Go format/vet/race tests, frontend checks/build, and the protocol v8 drift check.

When editing commands or results, change the Pydantic source models and regenerate the JSON Schema and Go structs. When adding a provider, implement `ProviderAdapter` v2 and register it through the `strix.providers` entry-point group.

Do not restore scan flags, headless execution, browser mutations, or environment precedence over AppConfig v3.

## Release gate

Tag builds additionally require two real, distinct provider accounts. Configure repository secrets named `STRIX_RELEASE_PROVIDER_A_ID`, `STRIX_RELEASE_PROVIDER_A_MODEL`, `STRIX_RELEASE_PROVIDER_A_API_KEY` and the matching `B` values. `STRIX_RELEASE_PROVIDER_A_BASE_URL` and `STRIX_RELEASE_PROVIDER_B_BASE_URL` are optional for compatible gateways. The gate sends one minimal response request to each provider and verifies that the router revision moves the second logical turn to provider B; it never prints keys, endpoints, prompts, or responses.
