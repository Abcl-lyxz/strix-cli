## Automatic routing

Each logical turn supplies an agent role, scan phase, required tools, vision requirement, estimated context/output, and remaining budget. The router rejects candidates with invalid auth, insufficient capabilities or context, open circuits, low-confidence metadata, or excessive projected cost.

Eligible routes are sorted deterministically by task quality tier, rolling reliability, capability fit, cost, latency, and stable model ID. Selection occurs at a logical-turn boundary or after a connection/model/policy revision; an in-flight stream is never switched.

`/router` shows eligible models, rejection reasons, health, current policy, decision history, and fallback history. Redacted decisions are also written into the run artifacts.

## Recovery bounds

- At most three distinct provider routes are attempted per logical turn.
- No retry or route change occurs after streamed output or a side-effecting tool call.
- One automatic resume is allowed only from a checkpoint with no side effect.
- Retry input waste is bounded by the configured multiplier and remaining cost budget.
- Three consecutive failed logical turns open the circuit and require user action.
- “Recovered” is emitted only after a complete successful response following a failure.

## Storage

```text
~/.strix/config.json       # AppConfig v3 and non-secret references
strix_runs/<run-name>/     # report, findings, logs, transcript, graph, router decisions
```

Legacy run evidence remains readable. Resume is restricted to the current run schema.
