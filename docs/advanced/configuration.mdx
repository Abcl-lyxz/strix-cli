---
title: "AppConfig v3"
description: "Configuration ownership and apply scopes in Strix v2"
---

Strix stores its v2 configuration at `~/.strix/config.json`. `ConfigService` is the only writer and validates the complete document before an atomic replacement.

The document owns provider connections, enabled model descriptors, router policy, scan defaults, MCP connections, notification preferences, and UI preferences. Credentials are secret references, never reusable plaintext.

## Clean break

Strix does not migrate, delete, or overwrite `cli-config.json`, legacy route files, or legacy keychain records. A malformed v3 document raises a visible error and preserves the last-known-good object; it is never interpreted as an empty configuration.

Environment values are read-only detection hints exposed by provider adapters. They cannot silently replace the connection, model, or policy chosen in the TUI.

## Apply scopes

Every typed setting declares one scope:

- `immediate` affects UI/application behavior immediately.
- `next_request` is read at the next logical model turn.
- `next_scan` is copied into the next immutable `RunConfig`.
- `restart` requires restarting Strix.

Use `/settings` to inspect both the value and its scope. Use `/connect` and `/models` for provider state; provider credentials are not general settings.

## Secret lifecycle

Connection rotation writes the new secret, commits the new profile revision, and only then deletes the old reference. Failed transactions remove the newly created reference. Disconnect removes the connection's owned secret after the config transaction succeeds.
