---
title: "Targets and Instructions"
description: "Define scope and guidance in the Strix v2 scan draft"
---

Use `/targets` in the TUI to add and remove URLs, repositories, directories, domains, IPs, API specifications, or Postman inputs. Use `/attach` for supporting context that is not itself a target.

Write the scan instruction in the launch workspace. Multiline input stays intact; use the editor command when the instruction is long. Scope, scan mode, budget, turn and agent limits, cache, streaming, and reasoning belong in `/settings`.

The editable `ScanDraft` is frozen into an immutable `RunConfig` when `/start` succeeds. Changes made later apply only according to each setting's declared scope.

Never put reusable credentials in scan instructions. Provider credentials belong in `/connect`; application test credentials should use the narrowest safe mechanism available for the authorized target.
